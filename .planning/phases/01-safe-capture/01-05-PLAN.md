## Phase Goal

**As a** single developer who captures learnings from the terminal on Windows, **I want to** install `til` once and record a one-line learning from any shell into today's local-date Markdown file, **so that** every entry is kept exactly as typed — Korean and emoji included — across repeated runs, concurrent runs, and failed writes.

> Derived verbatim from the ROADMAP Phase 1 **Goal:** line (role from PROJECT.md), same as plans 01-01..01-04.

<objective>
Close UAT gap G-01-2. On CI run 37210646435, windows-latest with Node 24 failed `npm run test:stress`: 20 parallel first-of-day writes produced two `# YYYY-MM-DD` headings. This plan removes the root cause and makes the gate real evidence.

Root cause (from .planning/debug/duplicate-day-heading-concurrent.md): `appendEntry` creates the day file with `openSync(file,'ax')` and writes heading+entry in a separate call, so the file is visible at 0 bytes for a moment. `appendExisting` then decides "write a heading" from `fstat size === 0` and cannot tell a really empty file from that in-flight moment. The fix keeps the existing heading logic unchanged but runs it only while holding a per-day lock, per D-11 ("add a short retry ... and/or a lock file"). That lock is an empty directory created atomically with `mkdirSync`. A 0-byte state seen while holding the lock can therefore never be another writer's half-finished state. Appends to a non-empty day file stay lock-free. The stress gate is pinned to 2 CPUs and runs 40 trials, so it triggers the race on Windows. It is also checked against the pre-fix code to prove it would have failed.

Mechanism choice (planner's discretion inside D-11, rejected routes recorded for the SUMMARY):
- Temp file + `linkSync`: rejected. It conflicts with D-10 (no temp files; every entry is one O_APPEND write), and hard links fail on FAT/exFAT.
- Bounded re-check of `size === 0`: rejected. It still decides from a 0-byte state that may be temporary (the window only gets longer), and two writers to a touched 0-byte file would still both write headings.
- Windows exclusive share mode: rejected. It needs an undocumented libuv flag, works only on Windows, and Linux would keep the race.
- Lock file opened with `ax`: rejected in favour of a lock directory. A directory has no content, nobody keeps a handle open on it, and antivirus scanners leave it alone. `mkdir` is atomic on NTFS, FAT/exFAT, SMB and POSIX.

Purpose: SC3's "20 parallel `til` runs leave all 20 entries, each exactly once, under exactly one heading" holds under CPU contention on every OS, and a green CI is real evidence of that.
Output: `src/storage.ts` with the per-day lock; storage, static and stress test changes; a contended `scripts/stress.mjs`; CI job timeout.
</objective>
